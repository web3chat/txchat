# GroupManage 仪表盘活跃指标功能备忘录

## 概述

在 groupmanage 后台管理系统的仪表盘中新增「每日活跃地址」和「群组活跃数量」两个实时指标，并附带占比显示。

---

## 新增指标

| 指标 | 含义 | 数据来源 | 查询逻辑 |
|------|------|---------|---------|
| **每日活跃地址** | 今日活跃的去重用户数 | `dtalk_signal_content` 表 | `COUNT(DISTINCT uid) WHERE create_time >= 今日0点 AND create_time < 明日0点` |
| **活跃占比** | 每日活跃地址 / 总用户数 | 前端计算 | `count / totalUsers * 100` |
| **群组活跃数量** | 今日有消息的活跃群组数 | `dtalk_msg_relation` 表 | `COUNT(DISTINCT other_uid) WHERE type = 1 AND create_time >= 今日0点 AND create_time < 明日0点` |
| **群组活跃占比** | 活跃群组数 / 总群组数 | 前端计算 | `count / totalGroups * 100` |

---

## 涉及文件及修改

### 1. DAO 层 — `dao/groupinfo.go`

新增两条 SQL 常量和两个接口方法：

**SQL 定义：**
```sql
-- 每日活跃用户数
_GetTodayActiveUserCount = `SELECT COUNT(DISTINCT uid) as count FROM dtalk_signal_content WHERE create_time >= ? AND create_time < ?`

-- 每日活跃群组数
_GetTodayActiveGroupCount = `SELECT COUNT(DISTINCT other_uid) as count FROM dtalk_msg_relation WHERE type = 1 AND create_time >= ? AND create_time < ?`
```

**接口定义：**
```go
GetTodayActiveUserCount(ctx context.Context) (int64, error)
GetTodayActiveGroupCount(ctx context.Context) (int64, error)
```

**实现要点：**
- 使用 `d.mysqlRecord.Query()` 查询 record 库
- 时间范围取 `todayStartUnix` ~ `tomorrowStartUnix`（当日 0 点到次日 0 点）
- 查询失败时返回 0，不中断主流程

### 2. Biz 模型层 — `model/biz/groupinfo.go`

在 `GroupStats` 结构体中新增两个字段：

### 3. Service 层 — `service/service.go`

在 `GetGroupStats()` 方法中追加活跃指标查询：

```go
func (s *Service) GetGroupStats(ctx context.Context) (*biz.GroupStats, error) {
    stats, err := s.groupInfoDAO.GetGroupStats(ctx)
    if err != nil {
        return nil, err
    }
    // 每日活跃指标（查询失败不中断主流程，静默降级为 0）
    if activeUsers, err := s.groupInfoDAO.GetTodayActiveUserCount(ctx); err == nil {
        stats.TodayActiveUsers = activeUsers
    }
    if activeGroups, err := s.groupInfoDAO.GetTodayActiveGroupCount(ctx); err == nil {
        stats.TodayActiveGroups = activeGroups
    }
    return stats, nil
}
```

**关键设计：** 活跃指标查询失败时静默降级，不影响原有群组统计数据的返回。

function updateTodayActiveCount(countId, count, total, ratioId) {
    const el = document.getElementById(countId);
    if (el) {
        el.textContent = formatNumber(count);
        el.classList.add('updated');
        setTimeout(() => el.classList.remove('updated'), 500);
    }

}

## API 返回示例

`GET /api/v1/groupmanage/groups/stats` 响应：

```json
{
  "code": 200,
  "message": "success",
  "data": {
    "totalGroups": 1234,
    "activeGroups": 1000,
    "bannedGroups": 200,
    "dissolvedGroups": 34,
    "todayActiveUsers": 567,
    "todayActiveGroups": 89
  }
}
```

占比由前端根据 `todayActiveUsers / totalUsers` 和 `todayActiveGroups / totalGroups` 计算。

---

## 数据库表说明

| 表名 | 用途 | 关键字段 |
|------|------|---------|
| `dtalk_signal_content` | 用户信号记录，用于统计活跃用户 | `uid`, `create_time` |
| `dtalk_msg_relation` | 消息关系记录，用于统计活跃群组 | `other_uid`（群ID）, `type`（1=群聊）, `create_time` |

---

## 设计决策

1. **静默降级**：活跃指标查询依赖 record 库，若连接失败则降级为 0，不影响原有群组统计
2. **占比前端算**：避免后端多一次查询 totalUsers/totalGroups，复用已加载的数据
3. **复用现有 API**：不新增独立接口，将活跃指标追加到 `/groups/stats` 响应中
4. **时间范围**：基于服务器本地时区取当日 0 点到次日 0 点
